## Role Assignment

| Work | Owner |
|------|-------|
| Hero images | **GPT** (image generation, outside this repo) |
| Everything else — `articles.json`, `styles.css`, `script.js`, `scripts/`, config, infrastructure | **Claude Code** |

Claude Code owns article content as well as the code. There is no separate content
agent: write articles directly into `articles.json` following the schema in
`AGENTS.md` and the enforced category/tag lists below.

The one thing Claude Code does not produce is imagery. Hero images are generated
with GPT and dropped into the repo; everything downstream of that is automated.

### Hero image workflow

1. Generate the image with GPT. Landscape, 3:2 — the existing set is 1536&times;1024.
2. Save as `assets/images/<article-id>.webp`, matching the article's `id` exactly.
   The filename is the only link between an article and its image.
3. Run the variant generator so `srcset` has a small version to serve
   (cards display at ~400-850 CSS px; without this every card downloads the full file):

   ```
   python scripts/make-image-variants.py
   ```

   It writes `<article-id>-800.webp` and skips anything already up to date.
4. In `articles.json` set:
   - `heroImage` — the **absolute** production URL,
     `https://raynart.github.io/TABI/assets/images/<article-id>.webp`.
     `Get-ImageSize` maps it back to the local file to emit `width`/`height`, so a
     relative path silently costs you the layout-shift protection.
   - `heroImageAlt` — required whenever `heroImage` is set.
   - `heroImageCredit` — `AI-generated image by OpenAI` for GPT images. All 63
     current images use exactly this string; disclosure of AI imagery is the point,
     so do not drop it.
5. Regenerate the site. If an image is replaced in place rather than renamed, bump
   `$imageVersion` in `generate-pages.ps1` or browsers will keep the stale copy.

## Monetization

Everything lives under `monetization` in `site.config.json` and is **off until filled in**.

| Setting | Effect when set |
|---------|-----------------|
| `adsense.clientId` | Enables ad markup, the cookie banner, the AdSense section of privacy.html, and `ads.txt` |
| `adsense.inArticleSlot` / `endOfArticleSlot` / `inFeedSlot` | Each renders that one slot; leave blank to skip it |
| `adsense.afterSection` | Which section the mid-article unit follows (auto-skipped on short articles) |
| `partners[].url` | A partner with no URL is never rendered — no dead affiliate links can ship |

Rules that must not be quietly undone:

- The AdSense library is fetched by `script.js` **only after cookie consent**. Never move it into `<head>`.
- Affiliate links carry `rel="nofollow sponsored"`. Dropping `sponsored` is a Google link-scheme violation.
- Articles carrying a paid link render the disclosure above the fold (`Get-AffiliateDisclosure`).
- Ad units are labelled "Advertisement" — required for AdSense, and doubly so on a site this quiet.
- `ads.txt` is generated from `clientId` and deleted when it is cleared. Do not hand-write it.

## PowerShell Encoding Rule

Never write Japanese directly in `.ps1` files — causes garbling.  
Always use HTML entities.

```powershell
# Bad
$lines.Add('旅')

# Good
$lines.Add('&#26053;')
```

## Local Preview

Every page has `<base href="$siteUrl/">`, so a production build cannot be previewed
locally — the browser would fetch CSS, JS and links from the live site. Build against
a local origin instead:

```powershell
$env:TABI_SITE_URL = "http://localhost:8080"
powershell -ExecutionPolicy Bypass -File ".\scripts\generate-site.ps1"
python -m http.server 8080
```

**Re-run the generator without `TABI_SITE_URL` before committing**, or the committed
HTML will point at localhost.

## Encoding

`articles.json` was once corrupted by a script that read it with `Get-Content -Raw`
without `-Encoding UTF8`; PowerShell 5.1 defaults to ANSI (CP932 here), which turned
every em dash and curly quote into mojibake. Always pass `-Encoding UTF8` when
reading, and write with `New-Object System.Text.UTF8Encoding($false)`.

The `.ps1` files themselves have no BOM, so **PowerShell 5.1 reads them as ANSI**.
Any non-ASCII character written literally in a script will be mangled on output —
use HTML entities or numeric character references instead (this is the existing
"never write Japanese directly in .ps1" rule, and it applies to `—` and `'` too).
